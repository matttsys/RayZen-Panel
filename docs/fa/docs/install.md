# :material-rocket-launch-outline:{ .md .middle } نصب و راه‌اندازی

RayZen روی حساب Cloudflare خودتان مستقر می‌شود. هیچ سروری از RayZen در این مسیر دخیل
نیست و هیچ چیزی که وارد می‌کنید به کسی جز Cloudflare نمی‌رسد.

## چه چیزی لازم دارید

- یک [حساب Cloudflare](https://dash.cloudflare.com/sign-up/) رایگان با ایمیل تأییدشده.
- یک زیردامنه‌ی `workers.dev` روی آن حساب، از مسیر
  **Workers & Pages → حساب شما → Subdomain**. این کار فقط یک بار انجام می‌شود؛ بدون آن
  Worker بدون مشکل مستقر می‌شود ولی آدرسی ندارد.

همین. بدون توکن API، بدون VPS، بدون خط فرمان.

## استقرار با یک کلیک

[مخزن RayZen](https://github.com/matttsys/RayZen-Panel) را باز کنید و دکمه‌ی
**Deploy to Cloudflare** را در README بزنید.

بعد از آن Cloudflare:

1. از شما می‌خواهد وارد شوید و اتصال GitHub را تأیید کنید.
2. RayZen را در حساب GitHub شما فورک می‌کند، پس کدی که Worker شما اجرا می‌کند مال
   خودتان است.
3. نام Worker را می‌پرسد. این نام، نام میزبان شما می‌شود
   (`<name>.<your-subdomain>.workers.dev`)، پس نامی انتخاب کنید که جلب توجه نکند.
4. فضای KV را می‌سازد، پروژه را بیلد و مستقر می‌کند.

یکی دو دقیقه طول می‌کشد.

## تکمیل راه‌اندازی

آدرس Worker خود را باز کنید. RayZen یک صفحه‌ی راه‌اندازی یک‌بارمصرف نشان می‌دهد:

1. ایمیلی که می‌خواهید با آن وارد شوید را بنویسید.
2. رمز عبوری انتخاب کنید. حداقل ۸ کاراکتر، یک حرف بزرگ و یک رقم لازم دارد.
3. دکمه‌ی **Create my panel** را بزنید.

بعد از آن RayZen آدرس پنل شما را می‌دهد.

!!! warning "همان لحظه آدرس را ذخیره کنید"
    این آدرس شامل یک مسیر مخفی تصادفی است که **فقط یک بار** نشان داده می‌شود و از
    داشبورد Cloudflare قابل بازیابی نیست. پیش از بستن تب، آن را در مدیر رمز خود ذخیره
    کنید.

    اگر گمش کردید، می‌توانید مقدار `securePath` را از کلید `rz:identity` در فضای KV
    خودتان، داخل داشبورد Cloudflare بخوانید.

## چه اتفاقی افتاد

Worker شما در نخستین درخواستش مسیر پنل، UUID مربوط به VLESS و رمز Trojan خودش را ساخت و
در فضای KV شما ذخیره کرد. هیچ‌کدام داخل کد جاسازی نشده‌اند و هیچ‌کدام بیرون از حساب
Cloudflare شما وجود ندارند.

## پنجره‌ی راه‌اندازی اولیه

بین پایان استقرار و کامل‌کردن آن صفحه‌ی راه‌اندازی، هر کسی که اول به آن برسد مدیر
می‌شود. در عمل این فاصله همان چند ثانیه‌ای است که شما کلیک می‌کنید، و هنوز کسی آدرس
Worker شما را نمی‌داند.

اگر می‌خواهید این پنجره در هر حالتی بسته باشد، *پیش از* بازکردن آدرس Worker یکی از
این‌ها را در **Settings → Variables and Secrets** اضافه کنید:

| متغیر | اثر |
|---|---|
| `RAYZEN_ADMIN_EMAIL` | راه‌اندازی فقط همین ایمیل را می‌پذیرد، پس تصاحب توسط دیگری حسابی می‌سازد که خودش نمی‌تواند با آن وارد شود. |

## اختیاری: فعال‌کردن امکانات Cloudflare

آمار مصرف، تنظیم دامنه‌ی اختصاصی از داخل پنل و استقرار مجدد ترمیمی به دسترسی API
Cloudflare نیاز دارند. دو مقدار را در **Settings → Variables and Secrets** اضافه کنید:

| متغیر | مقدار |
|---|---|
| `RAYZEN_CF_ACCOUNT_ID` | شناسه‌ی حساب شما، در صفحه‌ی نمای کلی Workers. |
| `RAYZEN_CF_API_TOKEN` | توکنی با دسترسی Workers Scripts · Edit و Workers KV Storage · Edit. |

بدون این‌ها پنل به‌طور عادی کار می‌کند و فقط همان امکانات را «در دسترس نیست» گزارش
می‌دهد. هر دو فقط از محیط خوانده می‌شوند و هرگز در KV نوشته نمی‌شوند، پس در خروجی
تنظیمات و فایل‌های پشتیبان ظاهر نمی‌شوند.

## به‌روزرسانی

فورک شما یک مخزن معمولی است. از upstream بگیرید، به فورک خودتان push کنید و Cloudflare
خودکار بیلد و مستقر می‌کند. تنظیمات شما در KV می‌مانند و از استقرار مجدد جان سالم به در
می‌برند.

## نصب بدون حساب GitHub

دکمه‌ی Deploy به یک حساب GitHub نیاز دارد تا مخزن در آن فورک شود. اگر حساب GitHub ندارید،
نصب‌کننده Worker را مستقیماً به API کلادفلر بارگذاری می‌کند:

```bash
npm ci
npm run build
npm run install:cloudflare
```

نصب‌کننده یک توکن API کلادفلر می‌خواهد، دقیقاً با سه دسترسی: **Workers Scripts: Edit**،
**Workers KV Storage: Edit** و **Account Settings: Read**. توکن را از
[dash.cloudflare.com/profile/api-tokens](https://dash.cloudflare.com/profile/api-tokens)
بسازید.

سپس نصب‌کننده یک نام تصادفی مثل `rayzen-swift-harbor` تولید و نمایش می‌دهد، فضای KV را
می‌سازد، Worker را بارگذاری می‌کند و آدرس نهایی را چاپ می‌کند. مراحل بعدی همان صفحه‌ی
راه‌اندازی یک‌بارمصرف است.

!!! info
    توکن فقط در همان دستور استفاده می‌شود؛ روی دیسک ذخیره نمی‌شود و داخل Worker قرار
    نمی‌گیرد. با `--dry-run` می‌توانید نتیجه را بدون ساختن چیزی ببینید.

## استقرار از ترمینال

اگر ترجیح می‌دهید فورک نکنید، کلون کنید و با wrangler مستقر کنید:

```bash
git clone https://github.com/matttsys/RayZen-Panel.git
cd RayZen-Panel
npm ci
npx wrangler kv namespace create rayzen --binding kv --update-config
npx wrangler deploy --name $(npm run -s name)
```

بعد آدرس Worker را باز کنید و همان صفحه‌ی راه‌اندازی را کامل کنید. راهنمای کامل شامل
همه‌ی متغیرهای محیطی و مسیر دامنه‌ی اختصاصی، در فایل `docs/DEPLOYMENT.md` مخزن است.

## قدم‌های بعدی

- یک [دامنه‌ی اختصاصی](configuration/admin-settings.md) اضافه کنید. `workers.dev` در
  بعضی شبکه‌ها مسدود است، پس بهتر است زود این کار را بکنید.
- [تنظیمات](configuration/index.md) را بررسی و اولین سابسکریپشن‌ها را بسازید.
- اسکنر اندپوینت را از تب Intelligence اجرا کنید تا آی‌پی‌های تمیز پیدا شوند.
